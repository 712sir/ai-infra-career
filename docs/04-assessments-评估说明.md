# 04 - Assessments（评估）目录说明

## 目录概览

`assessments/` 目录定义了 ai-infra-junior-engineer-learning 项目的完整评估体系。评估是学习闭环的关键环节——通过入学测验诊断基础、中期考试检验阶段性成果、期末实战验证综合能力，确保每位学习者都能获得客观、可量化的学习反馈。

---

## 目录结构

### 一、顶层文件

| 文件名 | 内容简介 |
|---|---|
| `README.md` | 评估体系总览：介绍评估的三个层次（入学诊断 → 中期检验 → 期末综合评价）、评估时间节点建议、补考与重修政策、成绩记录与证书颁发标准 |

---

### 二、Quizzes（测验）— `assessments/quizzes/`

测验是轻量级的书面测试，主要用于入学诊断和阶段性知识检验。每份测验包含选择题、填空题和简答题，有明确的及格线和答题时间限制。

| 文件名 | 内容简介 |
|---|---|
| `.gitkeep` | 占位文件，用于在 Git 中保留空目录结构 |
| `prerequisites-quiz.md` | **入学预备知识测验**：在学习正式开始前评估学习者的基础水平。测验范围涵盖：Python 基础语法与数据结构（40%）、命令行与 Shell 基本操作（30%）、计算机网络基础与 HTTP 协议（20%）、版本控制基础概念（10%）。共 50 题，满分 100 分，及格线 **70%**。未达标学员需先完成指定的补强学习内容后方可正式入学 |

---

### 三、Practical Exams（实战考试）— `assessments/practical-exams/`

实战考试是综合性的动手操作考核，要求学习者在规定时间内完成实际的编码、部署和系统搭建任务。考试结果以代码仓库、部署记录和演示答辩三种形式提交。

| 文件名 | 内容简介 |
|---|---|
| `.gitkeep` | 占位文件，用于在 Git 中保留空目录结构 |
| `midterm-practical.md` | **中期实战考试**：在完成 Module 001～005 后举行，检验前半段学习成果。考试内容包括：编写一个带 API 的 Python 微服务（编码任务，40%）、使用 Docker 容器化应用并编写 Dockerfile（容器化任务，30%）、部署到本地 Kubernetes 集群并配置 Service（部署任务，30%）。考试时长 4 小时，允许查阅速查表和官方文档，禁止 AI 辅助编码 |
| `final-practical.md` | **期末实战考试**：在完成全部 10 个 Module 后举行，综合评估整个课程的学习成果。考试内容为：从零搭建一个完整的 ML 推理服务系统，包括数据预处理 Pipeline（20%）、模型加载与推理 API（30%）、Docker + K8s 部署配置（25%）、Prometheus 监控指标接入与 Grafana Dashboard（15%）、项目文档撰写（10%）。考试时长为 2 天（可分阶段提交），独立完成 |

---

### 四、Rubrics（评分标准）— `assessments/rubrics/`

评分标准细则是所有实战考试的评分依据，确保评分过程公平、透明、标准化。

| 文件名 | 内容简介 |
|---|---|
| `.gitkeep` | 占位文件，用于在 Git 中保留空目录结构 |
| `project-rubrics.md` | **项目评分标准细则**（100 分制）：<br><br>- **代码质量**（25%）：代码风格与规范遵循（PEP 8）、命名清晰度、函数/模块设计合理性、错误处理完善度<br>- **功能完整性**（30%）：核心功能是否按要求实现、边界情况处理、测试覆盖率（要求 ≥ 70%）<br>- **基础设施配置**（20%）：Dockerfile 与 K8s 清单文件的规范性、部署可复现性、CI/CD 配置完整性<br>- **文档质量**（15%）：README 完整性、API 文档清晰度、架构图与部署说明<br>- **性能与优化**（10%）：API 响应时间、资源使用效率、是否有基本的缓存/瓶颈分析 |

---

## 评分等级与通过标准

| 等级 | 分数区间 | 说明 |
|---|---|---|
| **A（优秀）** | 90～100% | 全面掌握课程内容，具备独立的 AI Infra 工程实践能力。获得"优秀结业证书"并有资格成为社区 Mentor |
| **B（良好）** | 80～89% | 较好掌握课程核心内容，能够独立完成常规工程任务。获得"结业证书" |
| **C（合格）** | 70～79% | 基本掌握课程内容，在指导下可完成工作任务。获得"结业证书" |
| **F（未通过）** | < 70% | 尚未达到课程最低要求，需针对性补强后申请重修或补考 |

### 通过条件

1. **入学测验**：成绩 ≥ 70% 方可正式进入课程学习；未达标者需在 2 周内完成补强学习后重新测验
2. **中期考试**：成绩 ≥ 70% 方可进入后半段学习（Module 006～010）；不合格者有一次补考机会（补考题目与首考不同但难度相当）
3. **期末考试**：成绩 ≥ 70% 方可获得结业资格；不合格者需在 4 周后申请重考
4. **综合评分权重**：最终总评 = 平时作业（20%）+ 中期考试（30%）+ 期末考试（50%），总评 ≥ 70% 即可结业

## 评估时间节

| 节点 | 时间 | 方式 | 时长 | 及格线 |
|---|---|---|---|---|
| 入学测验 | 课程开始前 | 线上笔试 | 90 分钟 | 70% |
| 中期考试 | Module 005 完成后 | 实战编码 + 演示答辩 | 4 小时 | 70% |
| 期末考试 | Module 010 完成后 | 综合实战项目 | 2 天 | 70% |

---

> **提示**：请勿将评估视为单纯的"考试"。它们是学习过程中的里程碑——帮助你确认已掌握的知识、识别薄弱环节，并为你未来的求职面试积累可展示的实战项目。每个实战考试的作品都可以写入你的 GitHub Portfolio。
